The front door

One HTTP port serves /ws, /blob/<sha256> and /identity. Every request runs the same middleware pipeline before any route body: mark-private → admit → authenticate. Admission by Origin/Host happens before the bearer check, and a credential must arrive through exactly one channel.

The router

Routes and the middleware chain are wired once at start. The router is typed on Daemon, so every handler receives the owned world as context.

Admission runs before auth

The pipeline admits a request by Origin/Host first. Only an admitted request reaches the bearer check — so an unapproved origin never gets a chance to guess a token.

Origin matching lives in origin_allowed; the official client origin is a constant (OFFICIAL_ORIGIN).

Authenticating a request

The bearer credential arrives through exactly one of the Authorization header or a ?token= query parameter — never both. authenticate resolves the outcome as an Auth_Result.

Bounded token parsing

bearer_token rejects anything outside MIN_AUTH_TOKEN_BYTES…MAX_AUTH_TOKEN_BYTES before it ever compares — malformed input degrades, it never asserts.

Constant-time compare

secret_equal compares presented vs expected without an early-out, so a wrong token can't be timed byte by byte.

The routes

/ws upgrades into the transport layer; /identity answers the daemon's public identity (with CORS preflight); /blob/<sha256> gets and puts content-addressed blobs.
