One JSON library, three boundaries

"Turn a struct into JSON and back" is needed at three trust boundaries in this codebase — the internal wire protocol, the LLM provider APIs, and the models.dev catalog feed. It used to be implemented three times over, with three encoders, three escapers, and three opinions about numbers. That duplication has been folded into libs/json: one string escaper, one number-writer family, one streaming decoder, one re-exported tree parser. What is left at each boundary is not a separate codec but a thin adapter — a different strategy for driving the shared primitives, chosen to fit that boundary's trust and lifetime. This page walks the shared library, then each of the three layers, then what genuinely still differs.

Three layers at a glance

Layer Trust Encode Decode
wire internal RPC json.Emitter (depth + comma stack) json streaming token decoder → typed structs
provider LLM APIs json.write_* punctuation over io.Writer json tree parse (re-exported core) + local readers
catalog models.dev feed — (decode only) hybrid: streaming top-level scan + subtree parse

Every layer imports libs:json and nothing else for JSON. Neither encoder uses json.marshal. The provider and catalog decoders lean on the core:encoding/json tree parser — re-exported through libs/json/std.odin, so it too is reached only as json.*.

libs/json — the shared module

libs/json is the codebase's single JSON package. It bundles yuke's own encoders (write_string, write_u64, write_f64, write_raw), the stateful Emitter, the streaming token Decoder, and a small family of typed object read_* readers — and re-exports in std.odin the slice of core:encoding/json the codebase uses so callers never import it directly.

The one string escaper writes bytes as raw UTF-8, replacing invalid input with U+FFFD rather than erroring — so a malformed byte in an argument can never break the frame. Both the wire Emitter and the provider writers escape through it; there is exactly one copy.

The tree readers report (value, present, valid): a missing or null member is absent but valid; a present member of the wrong type or out of range is invalid. Provider and catalog both read their parsed trees through this one family.

wire — the stateful emitter

Emitter is a strings.Builder plus a depth and a first[32]bool stack that tracks whether the next member needs a leading comma. Containers push/pop depth; _sep emits the comma unless it's the first member of the current container.

wire — the streaming token decoder

Decoding never builds a value tree. Decoder is a thin alias over the re-exported json.Parser, and each type decodes token-by-token straight into its typed struct. Strings unquote into the parser allocator; numbers get explicit digit-length and range guards because parse_i64 silently wraps.

The streaming decoder returns a small Decode_Error; the wire layer maps that onto its own protocol validation. Validation is uniform: a local Field enum plus a seen: bit_set[Field], checked against the required set at the end; unknown enum strings and unknown discriminators return Validation_Error, propagated with or_return.

Closed unions are the intricate part. dec_find_tag snapshots the entire parser, scans ahead for the discriminator key skipping values, then rewinds so the field loop can re-read members in any order. Each arm then re-implements the same boilerplate by hand — a Field enum, a seen set, and explicit rejection of sibling keys that belong to other arms.

provider — punctuation by hand, tree on the way back

The provider encoder is thinner and blunter: request builders write braces and commas as literal strings over an io.Writer, calling the shared json.write_raw / json.write_string / json.write_u64 for the values. There is no depth/comma machinery — the writer is stateless. The primitives return an io.Error, but a request builder writes into a growing strings.Builder and ignores them: that buffer is in-memory and effectively infallible, so a body build fails at validation and tool-argument parsing, not at the punctuation writes.

Decoding, by contrast, parses a full value tree with the re-exported json parser. decode_json_object requires a single root object and trailing EOF, returning .Parse_Error otherwise — peer input is error-returned, never asserted; field access is permissive tree reads — missing and null both read as absent, and malformed usage counters collapse to zero rather than erroring.

catalog — hybrid scan

The catalog feed is large and mostly unwanted, so decode does two passes: a zero-alloc json.validate_value syntax check with a nil allocator, then a manual top-level walk that skip_values unwanted providers and only json.parse_values the selected subtrees. Those subtrees are read with the shared json.read_* readers.

Three memory models, still

Shared primitives did not collapse the lifetimes. Each boundary still owns its decoded bytes differently, because each has a different consumer and a different deadline.

wire — borrow into the frame arena

Unquoted strings live in the parser allocator; decoded structs are non-owning borrows valid only while that arena lives. Ownership leaves only through explicit *_clone deep copies. dec_fixed and dec_skip allocate nothing.

provider — scratch tree vs turn arena

The parsed tree lives in a per-event scratch arena, rewound to an Arena_Temp watermark after each event so its pages are reused. Anything kept past the event is cloned into the separate turn (retained) arena, which the scratch never aliases.

catalog — growing arena, owned output

A virtual.Arena backs the scratch objects and selection slices; everything kept in the Result is cloned into the caller's allocator and released by result_destroy.

What the library folded away — and what still differs

The consolidation into libs/json retired the duplication that used to sit across these three layers. What remains distinct is genuine — a per-boundary strategy, not a re-solved primitive.

One string / number writer

There were two escapers and two float encoders; now the wire Emitter and the provider writers both go through write_string / write_u64 / write_f64. Same job, one copy.

One tree reader family

Provider and catalog no longer each re-express missing/null/typed access. Both read parsed trees through the shared json.read_* readers returning (value, present, valid).

One json import

std.odin re-exports the core:encoding/json surface as compile-time aliases, so every caller imports only libs:json — and a symbol can be swapped for a local implementation in one place.

Stream vs. tree decode

wire decodes token-by-token straight into typed structs and never materializes a tree; provider and catalog parse to a json.Value tree and read it. Two decode strategies, chosen by trust and payload size.

Rewind-to-find-tag

dec_find_tag snapshots and rewinds the whole parser to tolerate any member order — a streaming-decode cost the tree layers don't pay, since a tree collapses each closed union to a few lookups.

Latched vs. error-returning encode

The wire Emitter latches failed and is checked once at the end; the shared write_* primitives return an io.Error instead — which the in-memory request builder discards. Two error conventions over one buffer.

The wire decoder is the one at the untrusted RPC boundary, and its tests define exactly which encodings are rejected — that strictness is why it streams into typed structs by hand rather than reading a permissive tree, and any further consolidation onto a tree would have to preserve it.
