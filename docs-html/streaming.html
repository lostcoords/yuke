Streaming a turn

A turn is one single-attempt provider request. Raw bytes arrive from libcurl, a generic SSE framer cuts them into event:/data: events, a per-provider decoder turns each event's JSON into neutral Stream_Events, and a deferred dispatch delivers them to the engine outside the curl region. Two per-turn arenas draw the only lifetime boundaries that matter.

The pipeline, in order

Ten stages carry a byte from the socket to the engine. The whole path lives in src/provider/ plus two libraries: libs/bindings/curl is the byte source, libs/http/sse is the framer. (The daemon's WebSocket transport in src/client/transport.odin is a different thing entirely — it is not on this path.)

  1. 1libcurl write callback — on_write hands the body chunk to the sink. curl.odin:775
  2. 2body sink & gating — turn_on_body checks status/encoding/budget, then feeds the framer. turn.odin:419
  3. 3SSE framing — feed → end_line assemble whole events across chunk boundaries. sse.odin:90
  4. 4per-event callback — turn_on_sse_event opens a scratch scope, decodes, commits. turn.odin:479
  5. 5protocol dispatch — decoder_decode routes to the active provider arm. decoder.odin:47
  6. 6provider decode — anthropic_decoder_decode / openai_chat_decoder_decode / openai_responses_decoder_decode.
  7. 7JSON parse — decode_json_object parses one data: payload into a scratch tree. decode.odin:18
  8. 8atomic commit — turn_commit makes produced events visible, arms a dispatch. turn.odin:504
  9. 9deferred delivery — turn_on_dispatch hands events to the engine, out of the curl region. turn.odin:600
  10. 10termination — curl EOF → turn_on_curl_done → turn_finalize, exactly one on_done. turn.odin:527

Bytes in, and the body sink

libcurl calls on_write from inside its own transfer. It sets an in_curl flag and forwards the chunk; returning the error sentinel is the only way to abort a transfer from a callback.

turn_on_body is the sink. Before a single byte reaches the framer it gates on content-encoding, on a non-2xx status (which is buffered as a bounded error prefix instead of streamed), and on the aggregate response budget. Only a healthy body reaches feed.

Framing event: / data:

The framer is a small incremental parser. Its Parser owns two reusable buffers — line (the current physical line) and data (the joined payload). A tail with no line end is stashed in line and resumed on the next feed; a CRLF split across two chunks is stitched by last_was_cr, and a BOM split across chunks by consume_bom.

A blank line dispatches the event, but only if a data: field was seen. end_line parses each field and keeps only data — event: and id: are read and dropped. Multiple data: lines join with a newline.

Bounded, never asserting

Line and event caps are 1 MiB each; overflow returns .Line_Too_Long / .Event_Too_Large, which turn_on_body maps to .Response_Too_Large. Peer bytes degrade; they don't crash the daemon.

Not a general SSE parser

Dropping event:/id: is safe here because all three providers put everything in data: — but it means this generic-looking libs/http/sse is really tuned to those three protocols.

One event, decoded

Every framed event lands in turn_on_sse_event. It wraps the decode in an arena_temp_begin/arena_temp_end scratch scope — so the whole JSON tree is rewound after the event — then commits whatever neutral events were produced.

decoder_decode is a thin union dispatch over the active provider decoder.

The Anthropic decoder is the exemplar: a true event-typed protocol with an explicit block lifecycle (message_start → content_block_start → content_block_delta → content_block_stop → message_stop) and strict index ordering. It parses the payload with decode_json_object then defer json.destroy_value.

The two OpenAI decoders solve a harder problem: they must synthesize block structure the wire never sends. Chat (openai_chat_decoder_decode) opens a block on the first choices[].delta and closes-then-reopens when the kind flips; Responses (openai_responses_decoder_decode) is event-typed like Anthropic but with a response.* vocabulary and no [DONE].

The neutral event model

All three providers converge on one block-structured stream: Stream_Block_Started → deltas → Stream_Block_Stopped → Stream_Done. The engine only ever sees this — never a provider's wire shape.

Commit, then deliver out of the curl region

User callbacks must never fire while we are inside libcurl's stack. So decoding only appends to the turn's event queue; turn_commit makes the batch atomically visible (rolling back to before if the decode failed, so nothing partial escapes) and arms a zero-delay nbio timeout. turn_on_dispatch then drains the queue to the engine on a clean stack.

How a turn ends

A turn walks Created → Running → Completing → Done (or Canceled). Termination has two sources: a protocol terminator decoded mid-stream (Anthropic message_stop, Chat [DONE], Responses response.completed), or curl EOF. On EOF, decoder_finish decides whether a stream that stopped early is complete or truncated — and that verdict differs per provider.

Two arenas draw every lifetime

The whole memory model is two OS-backed virtual arenas on the Turn. There is no per-object freeing anywhere on this path — decoders are written to never free.

retained — turn lifetime

The SSE parser buffers, the decoder's retained strings and tool-arg buffers, the event queue, the error-body prefix. Anything that must outlive an event is strings.cloned in here. Freed in bulk at turn_cleanup.

scratch — one event

The JSON value tree for a single event. Watermark-rewound after every turn_on_sse_event, so pages are reused. An assert forbids it from aliasing the turn allocator — a clone that forgot to switch arenas would trip it.

Emitted Stream_Event strings borrow retained and are valid only until the turn completes or cancels — the engine must clone anything it persists.

Where the weight is (for the rework)

The path is correct, but a few spots carry most of the incidental complexity — the places to look first if the goal is "simpler for what it does".

Two tool-emission timings

Anthropic emits tool start/stop inline at content_block_stop; both OpenAI decoders buffer every tool call and replay them only at the terminal. So "block order" is real for one provider and synthetic for the others — a subtle contract wrinkle for the engine.

Responses has three arg sources

openai_responses_finalize_tool picks arguments from the done item, else accumulated deltas, else {}. The delta-accumulation path may be dead if the .done item always carries full arguments — worth confirming against real payloads before the rework keeps it.

The Completing / dispatch handshake

The Completing state plus deferred dispatch is the most stateful piece here. It exists only to keep callbacks out of the curl region and after cancellation-safe borrows — justified by the in_curl invariant, but the part most likely to read as over-engineered.

Reasoning-signature dance

Responses can synthesize a start/stop pair for an encrypted-only reasoning block that never streamed text (capture_signature, finalize_reasoning). Legitimate, but the most intricate branch in the file.
